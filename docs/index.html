mi-portafolio

Sitio web personal desarrollado con React y Vite que centraliza proyectos, blog, componentes reutilizables, materiales de apoyo, aplicaciones de software y una sección sobre el autor. Desplegado en Firebase con CI/CD automatizado vía GitHub Actions.

React ^19.2.3 Vite ^7.2.4 Firebase Hosting Arquitectura MVC GitHub Actions CI/CD
01

Inicio Rápido

Para correr el proyecto localmente solo necesitas Node.js y npm. El proyecto usa Vite con Hot Module Replacement (HMR) para un ciclo de desarrollo ágil. 

# 1. Clonar el repositorio
git clone https://github.com/Mau-Noj/portafolio.git
cd portafolio/mi-portafolio

# 2. Instalar dependencias
npm install

# 3. Servidor de desarrollo con HMR
npm run dev

# 4. Build de producción optimizado
npm run build

# 5. Preview del build de producción
npm run preview
🔑
Nota sobre Firebase: Para desplegar manualmente necesitarás tener configurado Firebase CLI con las credenciales del proyecto. El despliegue automático vía GitHub Actions no requiere configuración adicional si los secrets de Firebase están registrados en el repositorio.
1

Clona y entra al directorio correcto

El código fuente de la app React vive en portafolio/mi-portafolio/, no en la raíz del repo.

2

npm install

Instala todas las dependencias listadas en package.json, incluyendo React, Vite, React Router y todas las librerías del proyecto.

Patrón Arquitectónico MVC

El proyecto implementa una arquitectura MVC (Model-View-Controller) adaptada al ecosistema de React. Cada capa tiene una ubicación concreta dentro de src/ y una responsabilidad bien definida.

VIEW
Interfaz de Usuario
src/views/ · src/components/ · src/apps/
PRESENTACIÓN
evento / callback
↓
CONTROLLER
Lógica de Negocio
src/controllers/ · src/hooks/
ORQUESTACIÓN
consulta / actualiza
↓
MODEL
Datos y Esquemas
src/models/
FUENTE DE VERDAD
💡
El flujo de datos es unidireccional: el usuario interactúa con la View → la View notifica al Controller → el Controller consulta/actualiza el Model → el nuevo estado vuelve a la View para re-renderizarse. Esta dirección constante hace el código predecible y más fácil de debuggear.

Prácticas Complementarias

Además del patrón MVC base, el proyecto incorpora tres prácticas que potencian la escalabilidad, el mantenimiento y la modularidad del código.

01
Organización
Feature-Based Structure
Las carpetas están organizadas por responsabilidad funcional en lugar de por tipo de archivo. Facilita localizar y modificar cualquier parte del sistema sin navegar estructuras arbitrarias.
src/models/ · src/controllers/ · src/views/
02
Estado
Custom Hooks Pattern
La lógica de estado reutilizable se encapsula en custom hooks dentro de src/hooks/. Evita duplicar lógica en múltiples componentes y mantiene los controladores limpios.
useDarkMode — gestiona tema oscuro/claro
03
Modularidad
Micro-frontend
src/apps/CartaNovia/ es una sub-aplicación completamente aislada del portafolio principal, con sus propios estilos y flujo interno. Demuestra la capacidad de construir módulos independientes dentro de una misma base de código.
Accesible en /software/:id/app

/contacto ContactSection Formulario de contacto integrado con EmailJS para envío directo de mensajes.

Modelos de Datos

La carpeta src/models/ es la fuente única de verdad de todos los datos del portafolio. Los archivos *.data.js contienen datos crudos y los *.model.js definen los esquemas de cada entidad.

📌
Principio clave: Cambiar un dato en los archivos *.data.js se propaga automáticamente a todas las vistas que lo consumen, sin necesitar editar múltiples archivos dispersos por el proyecto.
projects.data.js
Lista de proyectos del portafolio con título, descripción, tecnologías usadas y enlaces al repositorio o demo.
software.data.js
Aplicaciones de software creadas, con metadatos completos y rutas a sus sub-aplicaciones (micro-frontends).
software.model.js
Esquema y estructura que debe cumplir cada objeto de software: campos requeridos, tipos y validaciones.
components.data.js
Componentes UI documentados disponibles en la sección /componentes del portafolio.
components.model.js
Estructura esperada de un componente documentado: nombre, descripción, props, ejemplos.
materials.data.js
Materiales de apoyo (guías, recursos, PDFs) listados en /materiales, con soporte para fórmulas KaTeX.
project-logs.data.js
Historial de actualizaciones de los proyectos (changelog). Visible en la vista de detalle de cada proyecto.

CI/CD Pipeline

El directorio .github/workflows/ contiene la configuración de GitHub Actions que automatiza completamente el ciclo de vida del despliegue. Cada push a master dispara el pipeline.

📤
Push
master branch
🔄
Trigger
GitHub Actions
📦
Install
npm install
⚙️
Build
npm run build
🚀
Deploy
Firebase Hosting
✅
Live
Producción
🔐
El despliegue automático funciona sin intervención manual siempre que los Firebase secrets estén correctamente registrados en el repositorio de GitHub (Settings → Secrets and variables → Actions). 
# .github/workflows/firebase-deploy.yml (estructura)
name: Deploy to Firebase Hosting

on:
  push:
    branches:
      - master

jobs:
  build_and_deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Install dependencies
        run: npm install
        working-directory: mi-portafolio
      - name: Build
        run: npm run build
        working-directory: mi-portafolio
      - name: Deploy to Firebase
        uses: FirebaseExtended/action-hosting-deploy@v0

Cómo Contribuir / Extender

El proyecto está diseñado para ser fácil de extender. Gracias a la separación MVC, agregar nuevas secciones, datos o funcionalidades sigue siempre el mismo patrón.

🗄 Agregar datos nuevos

  • Crear o editar el archivo *.data.js correspondiente en src/models/
  • Definir el esquema en un archivo *.model.js si la entidad es nueva
  • Los cambios se propagan automáticamente a todas las vistas

🖥 Agregar una nueva sección

  • Crear el componente de vista en src/views/NuevaVista.jsx
  • Registrar la ruta en App.jsx
  • Añadir el enlace de navegación en Navbar.jsx

⚙️ Agregar lógica de negocio

  • Crear un controller en src/controllers/
  • Si es lógica de estado reutilizable, usar un custom hook en src/hooks/
  • Importarlo en la vista o componente que lo necesite

🚀 Agregar una micro-app

  • Crear una carpeta nueva en src/apps/NuevaApp/
  • La micro-app puede tener sus propios estilos y estado sin afectar el portafolio
  • Registrar la ruta /software/:id/app en App.jsx
